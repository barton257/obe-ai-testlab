# cases/

test-strategy-generator 的历史修正案例。AI 生成首版 → QA 修正终版 → 记录原因。

## 触发条件

以下修改触发案例归档：

- 场景矩阵漏了关键维度（常见：并发轴、批次冲突轴、KYC 状态轴）
- DoD 映射漏项
- 非功能维度描述过泛（"要测安全"这种）
- 把运营参数写死
- 六问有格子空缺或答非所问
- 测试层次错配（例如把契约测试放到 UI E2E）

## 不触发

- 措辞润色
- 单个字段字面调整
- QA 补充业务背景（这个走"输入"层，不走"修正"）

## 归档结构

```
YYYY-MM-DD-<业务>-<功能>-<问题关键词>.md

- 首版摘要（错在哪）
- 终版摘要（改成什么）
- 修正理由（业务/规范/风险考量）
- 未来防错点（生成时应主动检查什么）
```

## 特有关注

策略文档是**用例的父层**，改一个策略字段会级联影响下游 testcase-generator 和 api-test-generator。修正时优先修**规则**（在 `prompt.md` 补自检项），案例作为佐证。
