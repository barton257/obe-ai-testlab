# walkthrough-recorder / cases

**已解决过的真实案例**归档。记录：AI 整理的原始走查报告 → 人工修改后的终版 → 修改原因。

同类目录说明见 `../../testcase-generator/cases/README.md`。

## 什么时候写一个 case

**walkthrough-recorder 触发条件**：

- AI 把不重要的观察当成主线（详略失衡）
- 遗漏了必要的分节（如"异常态""数据口径"）
- 把观察和结论混在一起
- 未按业务逻辑组织，只按时间顺序堆
- 术语不统一（同一概念多种叫法）
- 该保留的原始数据被过度总结掉

不写：段落顺序微调、标题措辞。

## 结构

沿用三段式：**Input**（原始笔记/流水）+ **AI First Draft**（AI 整理版）+ **Final Version**（终版），加一段 **学习点**。

## walkthrough-recorder 案例的特有关注

写案例时着重记录：

1. **分节心智模型**——你怎么决定"这段该单独成节 vs 合进上一节"
2. **详略取舍**——什么信息必须保留原文，什么可以概括
3. **观察 vs 结论的边界**——哪些能写进报告，哪些必须打上"待验证"标签
4. **口径统一**——同类现象在不同页面/接口的叫法如何统一
