# testcase-generator / cases

**已解决过的真实案例**归档。每个案例记录：AI 生成的原始版本 → 人工修改后的终版 → **修改原因**。

## 为什么要有这个目录

skill 的 `prompt.md` 告诉 AI "怎么做"，`cases/` 告诉 AI "**做错过什么**"。让 AI 从真实修正中学习，比让 AI 读 100 条抽象规则更有效。

## 什么时候写一个 case

**必写**：
- 你对 AI 生成的用例做了**结构性修改**（不只是改错别字）
- 修改揭示了 prompt 里没说清楚的规则
- 未来遇到同类场景，你会希望 AI 直接产出终版

**不必写**：
- 单纯的措辞润色
- AI 完美产出，你无改动
- 一次性、非典型的业务分支

## 案例结构

```
YYYY-MM-DD-{skill输入简述}.md
```

内容分三块：**Input**（输入了什么）+ **AI First Draft**（AI 首版关键片段）+ **Final Version**（终版 + 变更原因）。见现有案例作为模板。

## AI 使用规则

调用 `testcase-generator` 时：

1. 读 `prompt.md`（规则）
2. 扫 `cases/` 目录（学习历史修正）
3. 生成用例
4. 生成完毕在返回中标注："已应用案例 XX 的修正模式"

## Prompt 迭代回归

修改 `prompt.md` 后，把 `cases/` 里每个案例的 `Input` 部分重跑一遍，对比新输出与终版的差距：

- 差距变小 → prompt 优化有效
- 差距变大 → 回退或补规则
