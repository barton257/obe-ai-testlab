# [S2] 赎回金额远超权益时服务端静默截断到实际权益，无任何提示

- 环境：Testnet / API `bullapitest.1bullex.com`
- 复现率：2/2
- 提交人：Barton（AI 辅助）
- 日期：2026-08-17
- 影响接口：`POST /botapi/v1/invest/redeem`
- **严重级别演变**：初报 S1（潜在真扣款）→ 批次验证后确认 **S2**（静默截断而非拒绝）

## 复现步骤

用户 `10732164` 在机器人 1342 (Kakarotto) 的实际权益约 2.5 USDT：

```bash
curl -X POST 'https://bullapitest.1bullex.com/botapi/v1/invest/redeem' \
  -H 'authorization: Bearer <user1_token>' \
  -H 'content-type: application/json' \
  --data '{"userId":"10732164","botId":1342,"settleAmount":999999999}'
```

## 期望

服务端应显式拒绝并返回业务错误：

```json
{"code":1,"msg":"settle_amount_exceeds_equity","data":null}
```

原因：
1. 调用方（前端、集成方、自动化）需要知道请求未被完全满足
2. UI 才能提示"实际赎回 2.5 USDT"而不是显示"赎回 999,999,999 成功"
3. 符合防御性设计：接口做的事应与入参一致，越界应报错

## 实际

**同步阶段**：
- 返回 `{"code":0,"msg":"success"}`
- `invest/history` 立即出现新记录 `id=1820, tradeType=Redeem, status=Init, tradeAmount=2.499999, tradeUnits=2.540058`
- 服务端在**同步返回前已经截断了 settleAmount**，写入 history 的 amt 是截断后的值

**批次阶段（10 min 后）**：
- 同一条 id=1820 记录 `status=Finished, tradeAmount=2.49999915, tradeUnits=2.540058`
- 用户钱包 availableBalance 增加约 2.5 USDT
- **无 error log / 无告警 / 无二次通知**

## 关键证据

批次前后 history 快照（`scripts/verify_bug_s1.py` 输出）：

```
BEFORE redeem:  钱包 avail = 9552.72404043
调用 redeem(settleAmount=999999999)
同步响应 :      code=0 msg='success'
SYNC history:   #1820 Redeem Init amt=2.499999 units=2.540058
AFTER batch:    #1820 Redeem Finished amt=2.49999915 units=2.540058
                钱包 avail = 9552.22404043 → 变化仅 -0.5（含其他并发订阅测试的干扰）
```

**settleAmount 输入 999999999 → 实际处理 2.499999，静默丢失了 6 个数量级信息**。

## 为什么是 S2 而不是 S1

- 资金安全：✅ 未真扣超额（不越权，不错动资金池）
- 但主功能异常：❌ 接口的实际行为与调用方预期严重不一致
- 影响范围：所有走 redeem 接口的用户/集成
- 有 workaround：调用方必须自己先查权益、限制 UI 输入范围（对用户不友好）

按 [`shared/conventions/bug-severity.md`](../../../shared/conventions/bug-severity.md) 判定树第 4-6 步命中 S2。

## 为什么不是 S3

S3 是"不符合设计但埋雷不出事"。本 bug 会**当场误导用户**：UI 若显示"申请赎回 999999999"→ 用户以为发生了巨额赎回请求，结果批次结算 2.5，UX 极差。属于主功能异常。

## 相邻问题

- purchase 侧有前置校验 `balance_not_enough`，redeem 侧无对等校验
- purchase amount=0.5（低于最小值 1）也是静默通过（[S2 订阅金额穿透](2026-08-17-spartans-S2-订阅金额小于最小值未拦截.md)），与本 bug 属于**同一类"边界越界后静默处理"**的设计缺陷家族

## 建议

后端在 `redeem` controller 加：

```
if settleAmount > userEquity:
    return {"code": 1, "msg": "settle_amount_exceeds_equity", "data": {"maxAllowed": userEquity}}
```

前端拿到 `maxAllowed` 后可以提示用户"最大可赎回 X USDT"。
