## 三、测试用例明细

### 3.1 认证状态准备

文件：`auth.setup.ts`

#### 用例

1. 使用 `USER1_EMAIL`、`USER1_PASSWORD` 和 Testnet OTP 登录。
2. 登录后访问 Kakarotto 机器人详情页。
3. 将 cookie 和 localStorage 保存到 `.auth/user1.json`。
4. 后续 chromium 测试复用该认证状态。

#### 优点

- 接近真实用户登录过程。
- 避免每条业务用例重复登录。
- 每次执行重新生成认证状态，减少复用过期 cookie 的概率。
- 凭证从 `.env.local` 读取，没有写入测试代码。

#### 缺点

- 所有认证业务测试都依赖登录服务的可用性。
- 缺少账号配置时会导致整个 chromium 测试集失败。
- 固定 OTP `123456` 仅适用于当前 Testnet 环境。
- 已有测试产物中出现过登录态丢失，storageState 稳定性仍需验证。

### 3.2 登录流程

文件：`login.spec.ts`

#### 用例

1. User1 使用邮箱、密码和 OTP 登录成功。

#### 关键断言

- 登录后 URL 不再包含 `/login`。

#### 优点

- 覆盖真实 UI 登录流程。
- 登录凭证从环境变量读取。
- 缺少凭证时尝试跳过测试。

#### 缺点

- 只检查离开登录页，不能证明有效会话已经建立。
- 没有验证头像、昵称、用户菜单或认证接口。
- 没有覆盖错误密码、错误 OTP、空字段和 OTP 过期场景。
- 与 `auth.setup.ts` 重复执行相同登录流程。
- 用户信息断言仍处于待校准状态。

### 3.3 订阅 Happy Path

文件：`subscribe-happy.spec.ts`

#### 用例

1. 打开 Kakarotto 机器人详情页。
2. 点击订阅按钮。
3. 输入订阅金额，默认值为 1 USDT。
4. 勾选风险披露。
5. 点击确认并等待成功弹窗。
6. 打开"我的订阅"。
7. 检查页面中存在 Kakarotto。

#### 优点

- 覆盖订阅核心 P0 用户路径。
- 包含提交成功弹窗验证。
- 金额可通过 `SPARTANS_E2E_AMOUNT` 配置。
- 主要使用语义化 Playwright 定位器。

#### 缺点

- 每次运行都会产生真实订阅，测试不具备幂等性。
- 没有专用测试数据、数据清理或余额恢复机制。
- 最终只检查 Kakarotto 标题；历史订阅已存在时可能误通过（**待修复**，"我的订阅"列表 DOM 未校准）。
- 依赖 Kakarotto 始终处于 Running 且测试账户余额充足。
- 使用 `.nth(1)` 选择第二个订阅按钮，页面结构变化后容易失效。留档 trace 显示全量跑时该定位器解析到了机器人**列表页**的按钮并超时。

### 3.4 金额前端校验

文件：`subscribe-frontend-validation.spec.ts`

#### 用例（2026-08-18 更新）

1. 输入 `abc`，验证 number input 阻止非数字输入。
2. **✅ 空金额时确认按钮应禁用**（改用 `test.fail()` 标记已知缺陷）
3. **✅ 金额为 0 时确认按钮应禁用**（改用 `test.fail()` 标记已知缺陷）
4. **✅ 金额低于最小值（0.5 < 1）时确认按钮应禁用**（改用 `test.fail()` 标记已知缺陷）
5. 输入超过 input max 的金额，验证输入框仍能读回该值。

#### 优点

- 覆盖空值、零、低于最小值、非数字和超过最大值等边界。
- 对浏览器 number input 的原生行为有明确记录。
- 抽取了打开订阅弹窗的公共操作。
- 与测试策略和缺陷记录建立了关联。
- **✅ 改用 `test.fail()` 标记，断言正确预期，缺陷修复后自动变绿**

#### 审查意见勘误（2026-08-18 实测）

审查文档原称「已有失败报告显示 `0` 和 `0.5` 时按钮实际已经禁用，测试假设已经过期」。
单跑本文件复测，三个场景的确认按钮均为 `enabled`，**原缺陷记录成立，审查此条不成立**。
昨日全量跑产物里的 `disabled` 来自 storageState 失效后的未登录态，属 TODO P0-1 的副作用，
不是 min 联动生效。该现象已写进 spec 头部注释，避免后续再次误判。

#### 缺点

- 超最大值用例只检查输入框非空，没有验证按钮禁用、错误提示或提交被拒绝。
- `abc` 用例主要验证浏览器原生行为，对应用自身校验的覆盖有限。
- 没有覆盖负数、超过 6 位小数、科学计数法、Tier 最大边界等场景。
- 最小值隐含写死为 1，没有动态读取 Tier 配置。

### 3.5 风险披露

文件：`subscribe-risk-disclosure.spec.ts`

#### 用例

1. 打开订阅弹窗时，风险披露默认已勾选。
2. 取消勾选风险披露后，确认按钮应禁用。
3. 取消后重新勾选，确认按钮应恢复可用。

#### 优点

- 覆盖 checkbox 和确认按钮之间的完整状态转换。
- 正向验证关键合规控制。
- 每条用例相互独立。
- 测试意图清晰。

#### 缺点

- 使用 `force: true` 操作隐藏 checkbox，绕过真实用户交互层。
- 已有失败报告出现点击后 checkbox 状态未改变的情况。
- 更适合点击用户实际可操作的 label。
- "默认已勾选"是否符合产品和合规要求需要明确需求依据。
- 没有验证风险披露链接和披露内容。
- 确认按钮还受金额、认证等条件影响，失败原因可能不唯一。

### 3.6 国际化

文件：`subscribe-i18n.spec.ts`

#### 用例

覆盖 `zh-CN`、`en`、`zh-TW` 三种语言，每种语言包含以下两条测试：

1. 机器人详情页显示对应语言的订阅按钮。
2. 点击订阅按钮可以打开金额输入弹窗。

合计 6 条测试。

#### 优点

- 使用数据驱动方式生成测试，重复代码较少。
- 覆盖三种主要语言路由。
- 同时验证按钮文案和基础交互。
- 英文按钮使用大小写不敏感匹配。

#### 缺点

- 只验证订阅按钮，没有验证策略要求的金额单位和风险披露文案。
- 弹窗断言只查找任意带 placeholder 的 number input，范围偏宽。
- 使用 `.nth(1)` 选择第二个订阅按钮，定位稳定性不足。
- 已有失败报告显示登录弹窗可能遮挡订阅按钮。
- 没有测试从页面内切换语言，只测试直接访问不同语言 URL。
- 没有检查页面是否错误重定向到其他语言。
- 用例中的 `locale` 只用于命名，没有真正修改浏览器 locale。

### 3.7 未登录订阅

文件：`subscribe-logout.spec.ts`

#### 用例

1. 未登录用户可以浏览机器人详情页。
2. 页面显示登录入口。
3. 点击订阅后，接受跳转到 `/login` 或出现登录弹窗两种结果之一。

#### 优点

- 使用独立 anon project，不加载认证状态。
- 同时验证公开浏览和受限订阅。
- 能兼容跳转登录页和弹出登录框两种实现。

#### 缺点

- 如果产品已经确定唯一交互，就不应该同时接受两种结果。
- `Promise.race` 存在竞态，一个等待先超时可能造成误失败。
- 没有验证登录成功后是否返回原订阅上下文。
- 没有验证未登录用户不能直接调用订阅提交接口。
- 没有明确验证订阅弹窗未被打开。
